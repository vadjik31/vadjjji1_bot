# ДЕПЛОЙ НА RAILWAY — пошагово

Эта инструкция выкатывает бота на Railway так, чтобы он работал 24/7. Время: 15–20 минут, если делаешь впервые.

Cтоимость: trial credits бесплатно первые ~$5, потом hobby plan ~$5/мес.

## ШАГ 1 — Перевыпустить токен (важно!)

Токен бота был передан в открытом чате — он скомпрометирован.

1. В Телеграме: **@BotFather → /mybots → выбери своего бота → API Token → Revoke current token**
2. BotFather пришлёт новый токен — **скопируй его**, он понадобится в шаге 4
3. Старый токен сразу становится невалидным — никто им больше не воспользуется

## ШАГ 2 — Залить файлы на GitHub

Если git и терминал тебе непривычны — это нормально, всё делается через сайт.

1. Зарегистрируйся на [github.com](https://github.com) (если ещё нет аккаунта).
2. На главной жми зелёную кнопку **New** (создать репозиторий).
3. Имя — `amazon-bot`. Видимость — **Private** (важно, чтобы код не был публичным).
4. Жми **Create repository**.
5. На странице нового репо появится ссылка **uploading an existing file** — жми её.
6. **Перетащи в окно** все файлы из этой папки, КРОМЕ:
   - `RAILWAY_VARS.txt` (там твой токен — он не должен попасть в репозиторий)
   - `users.json` (если он у тебя появился)
   - `.env` (если ты его создавал)
   - папка `__pycache__/`

   Что точно нужно загрузить:
   - `bot.py`
   - `requirements.txt`
   - `Procfile`
   - `runtime.txt`
   - `Dockerfile`
   - `.gitignore`
   - `.env.example`
   - `README.md`, `НАСТРОЙКА.md`, `ДЕПЛОЙ.md`
   - `СЦЕНАРИЙ_БОТА.pdf` (опционально, для справки)

7. Внизу страницы — **Commit changes**.

## ШАГ 3 — Создать проект на Railway

1. Зайди на [railway.com](https://railway.com), залогинься через GitHub (кнопка «Login with GitHub»).
2. Жми **New Project → Deploy from GitHub repo**.
3. Если просит разрешение на доступ к репозиториям — дай, выбери `amazon-bot`.
4. Railway сразу начнёт сборку. Подожди 1–2 минуты — он установит зависимости.

После сборки бот **ещё не запустится** — токена нет. Сейчас добавим.

## ШАГ 4 — Добавить переменные окружения

1. В своём проекте Railway → клик по сервису → вкладка **Variables**.
2. Жми **+ New Variable** и добавь по одной:

| Name | Value |
|---|---|
| `BOT_TOKEN` | **новый токен** из шага 1 |
| `ADMIN_ID` | `630926654` |
| `CALL_LINK` | `https://t.me/vadjik` |
| `SITE_LINK` | `https://vadjik.com/` |

ADMIN_ID, CALL_LINK и SITE_LINK имеют дефолты в коде — можно не задавать, но лучше задать для гибкости.

3. После добавления Railway сам перезапустит сервис с новыми переменными.

## ШАГ 5 — Подключить Volume для сохранения данных

Без этого после каждого деплоя или перезапуска `users.json` (статистика воронки, прогресс пользователей) будет теряться. На реальном трафике это критично.

1. В сервисе Railway → **Settings → Volumes**.
2. **+ New Volume**:
   - Mount path: `/data`
   - Size: 1 GB достаточно
3. Создай.
4. Вернись в **Variables**, добавь ещё одну:

| Name | Value |
|---|---|
| `DATA_DIR` | `/data` |

5. Сервис снова перезапустится. Теперь `users.json` живёт в Volume и переживает все деплои.

## ШАГ 6 — Проверить, что работает

1. В Railway → **Deployments** → последний → **View Logs**. Должно быть что-то типа:
   ```
   INFO Бот запущен. ADMIN_ID=630926654, DATA=/data/users.json
   ```
2. Открой бота в Телеграме → `/start`.
3. Должно начать с приветствия и кнопки «Покажи, с чего начать».

Если ошибка `Conflict: terminated by other getUpdates request` — у тебя где-то ещё запущен этот же бот (на компе, например). Останови старый.

## ШАГ 7 — Прогнать всю воронку

1. `/start` → пройди до конца, не пропуская
2. Проверь:
   - Кружок «Кто я» приходит первым (после приветствия)
   - Видео 1 → 2 скрина-пруфа
   - Видео 2 → 4 скрина-пруфа
   - Видео 3 → текст-разворот
   - Кружок «Развилка» приходит после видео 3
   - На оффере две кнопки: «Результаты учеников» и «Записаться на разбор»
   - По «Результаты учеников» приходит 8 скринов + скрин сайта + кнопки «Открыть сайт» и «Записаться»
   - В конце квиза приходит кнопка «Написать @vadjik»
   - Тебе в личку прилетает уведомление с заявкой

3. Если что-то не так — `/reset` → пройти ещё раз. Меняй в `bot.py`, коммить → Railway пересоберёт.

## КАК МЕНЯТЬ ТЕКСТЫ ПОСЛЕ ДЕПЛОЯ

1. В GitHub открой свой репозиторий → `bot.py` → жми **карандашик** (Edit).
2. Внеси правки.
3. Внизу — **Commit changes**.
4. Railway сам увидит изменения и пересоберёт за 1–2 минуты.

## ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ

**В первую очередь — смотри логи** (Railway → Deployments → View Logs).

| Ошибка в логах | Что значит |
|---|---|
| `ОШИБКА: переменная окружения BOT_TOKEN не задана` | Не добавил BOT_TOKEN в Variables |
| `Unauthorized` или `401` | Неверный BOT_TOKEN (опечатка / старый) |
| `Conflict: terminated by other getUpdates` | Бот запущен где-то ещё одновременно (твой комп / другой деплой) |
| `ModuleNotFoundError` | Не подцепился `requirements.txt` — пересобери (Redeploy) |
| Бот не отвечает, в логах тишина | Сервис «спит» — проверь, что в Variables есть `BOT_TOKEN` |

## ЕСЛИ НУЖНО МИГРИРОВАТЬ С RAILWAY

Скачай `users.json` из Volume на свой компьютер (через Railway → Volumes → ... ). На новом хостинге залей в `DATA_DIR`. Все file_id и URL в `bot.py` продолжат работать — они не привязаны к хостингу, а к самому боту в Телеграме.
